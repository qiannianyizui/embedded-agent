# Phase 3A: Approval System Design

**Date:** 2026-07-17
**Status:** Approved
**Scope:** Dangerous tool call approval for CLI and Server modes

## Overview

Add an approval system that intercepts tool calls where `is_dangerous() == true`, pausing execution until a human confirms or rejects the operation. This is a **soft confirmation** layer that sits after the hard-blocking `SecurityPolicy` and before tool execution in `ExecuteToolsStep`.

**Design approach:** Interceptor pattern — inject `IApprovalHandler` into `ExecuteToolsStep`. CLI mode uses `StdinApprovalHandler` (stdin y/n/a), Server mode uses `PendingApprovalHandler` (condition_variable + HTTP resolve). No approval in Embedded mode (no interactive interface).

---

## 1. Core Interface

```cpp
// src/security/IApprovalHandler.h
#pragma once
#include <string>
#include "common/base/Types.h"  // json

namespace ea::security {

enum class ApprovalDecision { Approved, Rejected, Aborted };

struct ApprovalRequest {
    std::string tool_name;
    json arguments;
    std::string description;  // Human-readable description for display
};

class IApprovalHandler {
public:
    virtual ~IApprovalHandler() = default;
    virtual ApprovalDecision request_approval(const ApprovalRequest& req) = 0;
};

}  // namespace ea::security
```

**Key decisions:**
- `request_approval()` is **synchronous blocking** — the calling thread waits for user response
- `Aborted` means the user wants to terminate the entire agent loop (e.g. Ctrl+C), not just reject one call
- `description` is auto-generated by ExecuteToolsStep from tool_name + arguments

### Relationship with SecurityPolicy

| | SecurityPolicy | IApprovalHandler |
|---|---|---|
| Nature | Hard block (outright deny) | Soft confirm (wait for user) |
| When | Before approval check | Only when `is_dangerous() == true` |
| Result | Returns Error | Returns Approved/Rejected/Aborted |
| Example | ReadOnly mode blocks shell | Supervised mode shell needs confirmation |

Both are **chained**: SecurityPolicy first (hard block), then ApprovalHandler (soft confirm).

## 2. CLI Implementation — StdinApprovalHandler

```cpp
// src/security/StdinApprovalHandler.h
#pragma once
#include "IApprovalHandler.h"
#include <iostream>
#include <string>

namespace ea::security {

class StdinApprovalHandler : public IApprovalHandler {
public:
    ApprovalDecision request_approval(const ApprovalRequest& req) override {
        std::cout << "\n⚠️  Dangerous tool call requires approval:\n"
                  << "    Tool: " << req.tool_name << "\n"
                  << "    Args: " << req.arguments.dump() << "\n"
                  << "    [y/n/a(abort)] > " << std::flush;

        std::string input;
        if (!std::getline(std::cin, input)) {
            // stdin closed or Ctrl+C
            return ApprovalDecision::Aborted;
        }

        if (input == "y" || input == "Y") return ApprovalDecision::Approved;
        if (input == "a" || input == "A") return ApprovalDecision::Aborted;
        return ApprovalDecision::Rejected;  // default: reject
    }
};

}  // namespace ea::security
```

**Implementation notes:**
- Uses `std::cin` for input, compatible with existing CLI REPL
- `Ctrl+C` / stdin failure → `Aborted`
- Header-only, no additional dependencies

## 3. Server Implementation — PendingApprovalHandler

```cpp
// src/security/PendingApprovalHandler.h
#pragma once
#include "IApprovalHandler.h"
#include <atomic>
#include <condition_variable>
#include <map>
#include <memory>
#include <mutex>
#include <string>

namespace ea::security {

struct PendingApproval {
    std::string id;
    ApprovalRequest request;
    std::atomic<ApprovalDecision> decision{ApprovalDecision::Rejected};
    std::condition_variable cv;
    std::mutex mutex;
    bool resolved = false;
};

class PendingApprovalHandler : public IApprovalHandler {
public:
    explicit PendingApprovalHandler(int timeout_seconds = 300);

    ApprovalDecision request_approval(const ApprovalRequest& req) override;

    // Server-side: list pending approvals
    std::vector<PendingApproval*> pending_list() const;

    // Server-side: resolve an approval
    bool resolve(const std::string& id, ApprovalDecision decision);

private:
    int timeout_seconds_;
    mutable std::mutex mutex_;
    std::map<std::string, std::unique_ptr<PendingApproval>> pending_;
    int next_id_ = 1;
};

}  // namespace ea::security
```

**Interaction flow:**

```
1. Agent calls dangerous tool → request_approval() blocks on condition_variable
2. Server HTTP endpoint returns pending list to client
3. Client sends POST /approval/{id}/approve or /reject
4. resolve() wakes the blocked agent thread
5. Agent continues execution or returns error
```

**Implementation notes:**
- `request_approval()` blocks internally with `condition_variable::wait_for()` using timeout
- `resolve()` called by HTTP handler, notifies waiting thread
- Timeout: default 300 seconds, auto-reject on expiry
- `PendingApproval::decision` uses `std::atomic` for thread safety
- Pending approvals are cleaned up after resolution

## 4. ExecuteToolsStep Integration

```cpp
// src/agent/steps/ExecuteToolsStep.h (modified)
#pragma once
#include "agent/ITurnStep.h"
#include "security/SecurityPolicy.h"
#include "security/IApprovalHandler.h"

namespace ea::agent {

class ExecuteToolsStep : public ITurnStep {
public:
    ExecuteToolsStep(security::SecurityPolicy* policy = nullptr,
                     security::IApprovalHandler* approval = nullptr);

    Result<void> execute(TurnContext& ctx) override;
    std::string name() const override { return "execute_tools"; }

private:
    security::SecurityPolicy* policy_;
    security::IApprovalHandler* approval_;
};

}
```

**Execution flow (per ToolCall):**

```
for each ToolCall:
  1. SecurityPolicy::check_tool(tool_name)
     → fail → ToolResult{error, "blocked by security policy"}
  2. Find ITool, check is_dangerous()
     → true → ApprovalHandler::request_approval(request)
       → Rejected → ToolResult{error, "user rejected"}
       → Aborted  → ctx.should_stop = true, return
       → Approved → continue to execute
  3. Execute tool->execute(args)
  4. ToolOutputConfig truncation
```

**Connection to AgentLoop:**

`AgentLoop` constructor receives `IApprovalHandler*`, passes it to `ExecuteToolsStep`. CLI mode passes `StdinApprovalHandler`, Server mode passes `PendingApprovalHandler`, no approval needed passes `nullptr` (skip approval).

## 5. Configuration & main.cpp Integration

### TOML Config Extension

```toml
[security]
autonomy = "supervised"
workspace = "/home/user/project"
approval_timeout = 300

[security.approval]
mode = "auto"                      # stdin / pending / auto
auto_approve_dangerous = false     # Only effective in Full autonomy
```

### SecurityConfig Extension

```cpp
struct SecurityConfig {
    std::string autonomy = "supervised";
    std::vector<std::string> allowed_commands;
    std::string workspace;
    int approval_timeout = 300;              // New
    std::string approval_mode = "auto";      // New: stdin / pending / auto
    bool auto_approve_dangerous = false;     // New
};
```

### main.cpp Integration

```cpp
// Create ApprovalHandler based on config and runtime mode
std::unique_ptr<IApprovalHandler> approval;

if (security->level() == AutonomyLevel::Full && cfg.security.auto_approve_dangerous) {
    approval = nullptr;  // Full mode + auto-approve = no approval needed
} else if (cfg.security.approval_mode == "auto") {
    #ifdef EA_MODE_CLI
        approval = std::make_unique<StdinApprovalHandler>();
    #elif EA_MODE_SERVER
        approval = std::make_unique<PendingApprovalHandler>(cfg.security.approval_timeout);
    #else
        approval = nullptr;  // Embedded mode: no interactive interface
    #endif
} else if (cfg.security.approval_mode == "stdin") {
    approval = std::make_unique<StdinApprovalHandler>();
} else if (cfg.security.approval_mode == "pending") {
    approval = std::make_unique<PendingApprovalHandler>(cfg.security.approval_timeout);
}
```

**Key points:**
- `auto` mode selects based on compile-time `EA_MODE_*`, zero-config out of the box
- Embedded mode defaults to no approval (no interactive interface)
- `auto_approve_dangerous` only effective under Full autonomy; Supervised enforces approval

### MockApprovalHandler (for integration tests)

```cpp
class MockApprovalHandler : public IApprovalHandler {
public:
    ApprovalDecision next_decision = ApprovalDecision::Approved;
    ApprovalDecision request_approval(const ApprovalRequest& req) override {
        last_request = req;
        return next_decision;
    }
    ApprovalRequest last_request;
};
```

### Key Test Cases

1. Non-dangerous tool → no approval triggered, execute directly
2. Dangerous tool + Approved → normal execution
3. Dangerous tool + Rejected → ToolResult with error
4. Dangerous tool + Aborted → should_stop = true
5. SecurityPolicy blocks → approval not triggered (hard block takes priority)
6. PendingApprovalHandler timeout → auto-reject
7. PendingApprovalHandler multi-threaded resolve → correct wakeup
8. Null ApprovalHandler → dangerous tools execute without approval
